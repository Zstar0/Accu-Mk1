# HPLC Calibration Curve Worksheet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A chemist opens a Calibration Curve Worksheet in Mk1, types one standard's CoA
numbers, its stock weighings, the serial dilution weighings and later the peak areas, and files
a `calibration_curves` row that carries the net peptide weight derivation (inputs, the computed
factor, the applied factor, an override reason, which parts contributed) and the weighings it
was made from. "Duplicate for another injection" files the same vials again as -Inj2, or as
another instrument's own curve.

**Architecture:** Plan 4 of 5, spec section S9. The sheet's typed inputs live in ONE JSON column
on a new table, `hplc_calibration_sheets`, because a sheet is weighed days before it has peak
areas and `calibration_curves.slope`, `intercept` and `r_squared` are NOT NULL
(`backend/models.py:1017-1019`). Relaxing those would let a slope-less curve reach
`POST /hplc/analyze`, so they stay. "File curve" mints (or re-files) the curve row only once the
fit exists, and copies the net block and the weighings onto it. The working-out is one pure
function, `work_out_sheet`, written once in Python (`backend/hplc_calibration.py`) and mirrored
in TypeScript (`src/lib/hplc-calibration.ts`), both held to a fixture GENERATED by running the
lab tool's own `calc.js` in node, exactly as plan 3 pins `compute_row`. The page reuses plan 3's
cells and keyboard model.

Nothing in this plan changes what an existing curve route, screen or the results engine does.
Decision 18 (a hand-picked curve from another instrument is refused) is ALREADY BUILT on this
branch at `backend/main.py:7251`; do not plan or touch it. The one-active-curve index (decision
16) is Task 8 and is PARKED.

## Review Focus

Bench failures no task test would otherwise catch, each pinned by a test in the task named:

1. **A filed worksheet curve, then someone presses "Add Curve" (re-sync) on the Peptides page.**
   The re-sync deletes the curve. The sheet must survive with `calibration_curve_id` nulled, still
   hold every weighing, and offer "File curve" again, which mints a fresh row. Task 1 (the FK) and
   Task 5 (the route test).
2. **Re-filing a curve after analyses have used it** (a corrected weighing, a typed peak area). The
   slope would change under `hplc_analyses` rows computed with the old one. Refused with 409
   naming how many analyses use it; the curve row is byte-for-byte unchanged. The same refusal
   when re-filing an original would re-file a used replicate. Task 5.
3. **Filing on a peptide and instrument that already hold two active curves** (the dev copy's
   KISSPEPTIN-10 curves 81 and 90; prod's peptide 38 on instrument 2). The new curve files
   INACTIVE and neither old curve is touched, so the filing never pre-empts the Handler's ruling.
   Task 5.
4. **Changing the Instrument on a sheet whose curve is filed.** Re-filing would move a curve that
   analyses on one instrument used onto another. Refused with 409 pointing at "Duplicate for
   another injection". Task 4.
5. **The worksheet curve read through the Peptides page list.** `GET /peptides/{id}/calibrations`
   builds its response field by field (`_cal_to_response(include_blobs=False)`,
   `main.py:3749-3762`), so a key declared on the model but not added there vanishes, and with it
