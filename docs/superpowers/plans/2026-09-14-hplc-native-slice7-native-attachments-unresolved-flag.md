**Goal:** Close the three defects the 2026-09-14 devbox rehearsal found on the Mk1 side: (D1, blocker) a native-born parent has no way to receive a chromatogram or manual attachment, so COA generation hard-fails `422 missing_attachments: Chromatogram`; (D5) an unresolved analyte at registration leaves only `reportable_reason`, no flag (Handler ruling 4 says "seed the row with peptide_id NULL + flag"); (D3) the documented fallback placeholder seed logs `registry.native_placeholder_seed_failed` when it merely loses a benign race with the primary seed.

**Architecture:** All three attachment writers (`upload_chromatogram_to_senaite` `main.py:~6589`, `upload_senaite_attachment` `main.py:~16972`, receive step-1 image) funnel into `_capture_parent_attachment_bg` (`main.py:~18606`), which already resolves a native-born row by `sample_id` (slice 6) but is best-effort/swallowing. Both 409 `senaite_born_use_senaite_route` on a SENAITE-born row; the two legacy routes 409 `native_born_use_native_route` when handed a native-born row. FE: `SenaiteResultsView` and `SampleDetails` branch on `external_lims_system === 'mk1'`. Unresolved flag: the two seed sites (`lims_analyses/hplc_native.py` seed + `parent_placeholders.py`) raise ONE open flag per sample via the existing `_SystemActor` pattern (`sub_samples/service.py:~205`), dedup on `(sample, type, open)`, resolved automatically by `relabel_native_slot` when every slot resolves.
