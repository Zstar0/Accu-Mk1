# HPLC family → Mk1-native: new orders born native (program plan)

## Context
HPLC is the last SENAITE-born family. Every new peptide order still mints a SENAITE AR, the vial seeder copies the AR's analyte lines, and the catalog identity of every HPLC service is `origin=senaite`. Everything else is already Mk1-owned in prod (sample-tier status, COA generation reads `coa_generation: mk1` with zero SENAITE HTTP, vial-tier results, endo/PCR/USP71/HM native). Once new HPLC orders are born native, nothing new touches SENAITE and the disconnect can start after the legacy drain.

**Finish line (Handler 2026-09-10):** every NEW HPLC order is minted, benched, promoted and COA'd in Mk1 with no SENAITE AR. In-flight legacy samples finish on SENAITE and age out. Never flip `origin` on existing rows.

**Handler rulings (2026-09-10):**
1. Catalog shape **B**: generic native trio, `peptide_id` + `slot` + stamped `title` on the `lims_analyses` row; names derived from `peptides`; COABuilder page 1 untouched via a Mk1-side vocabulary shim.
2. Native-born samples keep the **`P-` / `PB-`** look; Mk1 counters seeded above SENAITE max.
3. Identity result = literal **`Conforms` / `Does Not Conform`**; spec = plain `equals "Conforms"` (no new rule kind).
4. Unresolved analyte name at registration → **seed the row with `peptide_id NULL` + flag** (visible, blocks COA, fixed by relabel).
5. Native **auto check-in for retests is required before the flip**.
6. Variance (`samplevariance`) must never mint an AR once the primary is native.
7. **Activation follows the endo/PCR convention**: NEW Mk1 profile key `hplc-purity-identity` + WP `profile_key` on the HPLC test-service row is the switch (rollback = clear it). The ~10 hardcoded `hplcpurity_identity` sites become alias-aware in this program.
8. Peptide ids are synced into WordPress (peptide items carry `peptide_id`; orders send it).
9. **Peptide Group** entity (blend composition template with variant choices, e.g. GLOW; TB-500 → {beta-4, 17-23} default + customer choice) = post-flip slice alongside the peptide-id sync.

Recommended defaults (override any time): counter seed P-5000 / PB-1000 + adoption guard; coab purity 98 hardcode stays; Bac Water stays SENAITE (own slice later); transfers of native samples 409 until a native transfer exists; WP dropdown goes Mk1-only at flip; shutdown gate = 0 non-terminal SENAITE-born samples for 14 days.

## Key design decisions (why)
- **Switch = WP `profile_key=hplc-purity-identity` on the HPLC primary row** (same as `endotoxin-usp85-lal`). WP's `serviceWireKey()` then emits the new key; IS has no `_map_services_to_profiles` arm for it → zero SENAITE profiles → native; the key reaches IS's registry via the existing Mk1 catalog sync. **Alias-set slice (pre-flip, behaviour-neutral):** every site that hardcodes `hplcpurity_identity` as "the primary" accepts BOTH keys — wpstar `IntegrationService.php:319-335` (variance points allow-list), `Vials.php:297,353` (`classify_service`), `Sample_Submission.php:108,669` (`CANONICAL_WIRE_KEYS`), `sample-submission.js:3872,3915` (`mk1Key`), `Addon_Upgrades.php:644`; IS `app/models/order.py:135-139` (declared field alias), `order_validator.py:559` (BW cross-check); Mk1 `sub_samples/service.py:1444` (`derive_variance_demand` hplc bucket = max over both keys), `:1485`, `seeder.py:80` (`ROLE_TO_WP_KEYS["hplc"]`), `product_registry.py:36`, `catalog/demand_verify.py:37`, `src/lib/product-completion.ts:119-136` (`HPLC_PACKAGE_KEYS`). Primary rows short-circuit the catalog-addon reclassification (`Front/MyAccount/Sample_Submission.php:342`), so the endo bundle trap does not bite; pin with a test anyway. Variance keeps key `samplevariance`; IS rule: when a peptide sample resolves zero primary SENAITE profiles, `sample_variance` yields no profile either (variance already rides `services.variance` to Mk1).
- **Legacy samples never order the new key**, so no phantom placeholders and `catalog_snapshot` freezes the trio's `service_ids` per native sample like every other native family. Mk1 still forks the seeder on `parent.external_lims_system == "mk1"` (belt and braces; also what the tees/shadow sync key on). Profile 1 `hplcpurity_identity` is left untouched (legacy). New profile `coa_archetype` stays NULL (no page-2 section for HPLC).
- **Five slot-blind partial unique indexes on `lims_analyses`** (`database.py:724-731,1137-1141,1726-1729,1799-1809`) must be widened to `(…, COALESCE(slot,0))` or a blend cannot hold N `HPLC-PURITY` rows.
- **Shim vocabulary must satisfy coab's ladder exactly** (`conformance.py:454-480,620-625,1176-1195`): identity Title == `Analyte{N}Peptide` == `"<name> - Identity (HPLC)"`, keyword `ANALYTE-{slot}-ID`; purity `ANALYTE-{slot}-PUR` (blend) / `HPLC-PUR` (single); quantity `ANALYTE-{slot}-QTY` (blend) / `PEPT-Total` (single); blend aggregates `BLEND-PUR` + `PEPT-Total`. Both `sample_meta` and `legacy_rows` derive from ONE helper so they cannot drift.
- **Peptide attribution joins use `COALESCE(LimsAnalysis.peptide_id, AnalysisService.peptide_id)`** (`coa/variance_series.py:180,239`, `coa/spec_rules.py:108-120`) or native rows vanish from variance pages / spec peptide tier.
- **Idempotent `/s2s/lims-samples`** is a flip prerequisite: a Mk1-committed-but-IS-timed-out retry with `sample_id=None` would mint a second sample (`sub_samples/service.py:310-317`).
